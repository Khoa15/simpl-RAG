# SIMPL-RAG

Upload documents (PDF, TXT, MD, CSV, DOCX, XLSX, and images via OCR) and ask questions across them.
No sign-up: the browser gets an anonymous session token on first visit.

## Architecture

- **API** (FastAPI): anonymous sessions, uploads, search, answers.
- **Worker** (Celery): parses files, embeds chunks in batches, writes to Qdrant, retries transient failures.
- **Beat** (Celery): removes data of users inactive for `DOCUMENT_TTL_SECONDS` (default 30 min).
- **Redis**: job queue, per-user document metadata, rate limits.
- **Qdrant**: one collection per user; each chunk is tagged with its document id.

## Run

```bash
cp .env.example .env        # fill in REDIS_PASSWORD, QDRANT_API_KEY, JWT_SECRET
docker compose up -d --build
docker compose exec api pytest tests -q   # integration tests against the live stack
```

Use `EMBEDDING_PROVIDER=local` to run without a Google API key (a FastEmbed model is downloaded once).
With `EMBEDDING_PROVIDER=gemini`, set `GOOGLE_API_KEY`.

## API

| Method | Path | Notes |
|---|---|---|
| POST | `/api/v1/session` | Returns an anonymous bearer token |
| POST | `/api/v1/documents` | Multipart `file`, returns `doc_id` and status `processing` |
| GET | `/api/v1/documents` | Your documents and their status |
| GET | `/api/v1/documents/{doc_id}` | One document's status and error code |
| DELETE | `/api/v1/documents/{doc_id}` | Removes the document and its vectors |
| POST | `/api/v1/search` | Top-k chunks with source (doc, page, sheet, rows) |
| POST | `/api/v1/retrieve` | Answer generated by the chat model (needs a Google key) |

## Limits

- File size: `MAX_UPLOAD_MB` (default 20). PDF pages: `MAX_PAGES` (default 300).
- Documents per user: `MAX_DOCUMENTS_PER_USER` (default 50).
- Rate limits: one upload per `UPLOAD_MIN_INTERVAL_SECONDS`, one query per `QUERY_MIN_INTERVAL_SECONDS`.
- Images are searchable by the text they contain (OCR). Visual similarity search is not supported.

## Issue a token for a known user (optional)

```bash
docker compose exec api python -m src.auth <user_id>
```

## Security notes

- Redis requires a password and is not published to the host. Qdrant requires an API key.
- Containers run as a non-root user with a read-only root filesystem.
- Identity comes only from the signed JWT `sub` claim; the client cannot choose a user id.
- Run behind HTTPS in production, and do not publish Redis or Qdrant ports.
